Dotfiles · предложение по архитектуре

Одно окружение.
Несколько NixOS и Mac.

Модули по фичам, каждый с одной системной точкой входа. Фича сама связывает установку, системную интеграцию и пользовательские настройки.

Исходные условия: один пользователь на всех машинах, общий набор приложений, поддержка только NixOS и macOS. Машин каждой ОС может быть несколько.

Основное решение

Home Manager встраивается в системную конфигурацию на обеих ОС. Поэтому модуль приложения может одновременно настраивать ОС и домашнее окружение через home-manager.users. Это штатная возможность интеграции Home Manager с NixOS и nix-darwin.

Снаружи подключается один SSH. Как он устанавливает пакет, настраивает агент и пишет пользовательский конфиг — ответственность самого модуля.

Да, hyprland/default.nix сможет подключать свою системную часть. Для этого default.nix становится системной точкой входа. Пользовательская часть подключается из него через Home Manager.

Граница между системными и пользовательскими опциями сохраняется. Но связывает эти части сам модуль фичи, поэтому отдельно перечислять их во flake и в общем Home Manager-конфиге не требуется.

Структура репозитория

flake.nix
lib/
└── mk-host.nix             # ОС + Home Manager + общий конфиг

shared/
├── default.nix             # единый список фич для всех машин
├── home.nix                # общая основа пользовательского окружения
├── nixos.nix               # общие настройки всех NixOS-машин
└── darwin.nix              # общие настройки всех Mac

hosts/
├── macbook/
│   └── default.nix
└── asahi/
    ├── default.nix
    └── hardware-configuration.nix

modules/
├── git/
│   └── default.nix
├── ssh/
│   ├── default.nix
│   ├── home.nix
│   ├── nixos.nix
│   └── darwin.nix
├── hyprland/
│   ├── default.nix
│   └── nixos.nix
└── ghostty/
    ├── default.nix
    └── files/
        └── config

Это пример возможных файлов. Создаём только те, в которых есть содержимое. Маленькому модулю достаточно default.nix; пять файлов на каждое приложение не нужны. Например, ssh/darwin.nix появится только при наличии отдельных настроек для macOS.

Имена home.nix, nixos.nix, darwin.nix обозначают внутренние части фичи. Единственная внешняя точка подключения у неё — default.nix. Исходники конфигов, темы и прочие dotfiles живут в её каталоге files/.

Один общий набор фич

shared/default.nix содержит единый список для всех машин:

{
  imports = [
    ../modules/git
    ../modules/ssh
    ../modules/codex
    ../modules/chatgpt
    ../modules/hyprland
    ../modules/ghostty
  ];
}

Каждая фича внутри определяет, что делать на выбранной ОС. Hyprland на macOS ничего не добавляет; приложение только для Mac ничего не добавляет на NixOS. Это осознанное поведение, позволяющее сохранить общий список приложений.

Приложения из списка выше иллюстрируют схему. Их наличие в примере не означает, что соответствующие модули уже реализованы.

Разные типы приложений

СлучайЧто делает модуль
Приложение только для MacУстанавливает и настраивает его только на macOS.
Приложение для обеих ОСПрименяет общую конфигурацию, например общий пользовательский модуль.
SSH с различиями между ОСПодключает общий пользовательский конфиг и нужную системную часть.
HyprlandНа NixOS включает системную интеграцию и, когда появятся, пользовательские настройки.
Разный способ установкиНа одной ОС использует Nix-пакет, на другой — другой механизм, сохраняя общий конфиг.

Последний случай существенный: GUI-приложение на Mac может устанавливаться через homebrew.casks в nix-darwin, а его настройки управляться Home Manager. Поэтому привязывать «приложение» исключительно к Home Manager неудобно. Документация nix-darwin.

По той же схеме можно оформить системную возможность: Bluetooth, аудио или шрифты. У модуля не обязана быть пользовательская часть.

Пример точки входа SSH

# modules/ssh/default.nix
{ lib, host, ... }:

{
  imports =
    lib.optionals (host.os == "nixos") [ ./nixos.nix ]
    ++ lib.optionals (host.os == "darwin") [ ./darwin.nix ];

  home-manager.users.${host.user}.imports = [ ./home.nix ];
}

host.os и host.user задаются при сборке хоста и передаются через specialArgs. Имя единственного пользователя задаётся централизованно, чтобы не повторять его в каждом модуле.

Общий SSH-конфиг существует в одном экземпляре — home.nix. NixOS-опции попадают только в NixOS, Darwin-опции — только в Darwin. Пример показывает вариант с обеими системными частями; если отдельной части пока нет, её файл и импорт не нужны.

Для Hyprland принцип тот же: его точка входа подключает NixOS-часть только на NixOS. Если позже появится пользовательский конфиг с биндами и оформлением, он подключается внутри этого же модуля.

Обязанности каталогов

МестоОтветственность
flake.nixЗависимости и перечень машин.
lib/mk-host.nixСборка хоста: нужная ОС, интеграция Home Manager, общая конфигурация и конфигурация конкретной машины.
shared/default.nixЕдиный список подключённых фич.
shared/home.nixПользовательская основа: например, home.stateVersion и общие переменные окружения.
shared/nixos.nix
shared/darwin.nix		Общая политика соответствующей ОС. Настройки конкретных фич остаются внутри их модулей.
hosts/<имя>Hostname, железо, диски, загрузчик, особенности мониторов и другие отличия машины.
modules/<фича>Установка, конфиги, системная интеграция и различия между ОС для одной фичи.

shared/home.nix не становится вторым списком приложений: приложения подключаются через единый список фич. Системные части SSH или Hyprland также не перечисляются отдельно во flake.

Несколько машин

Новый Mac получает общую конфигурацию Mac и весь подходящий набор приложений. Новая NixOS-машина — общую конфигурацию NixOS и подходящий ей набор.

Если у рабочего ноутбука другой Git email или у десктопа другие мониторы, это задаётся в соответствующем хосте. Общему модулю не нужно проверять имена машин.

Отличия хоста могут относиться и к системе, и к домашнему окружению. Критерий размещения — принадлежность настройки конкретной машине.

Что пока не нужно

Профили work, personal, desktop пока не вводим: выбран общий набор для всех машин. Начинаем с явного списка imports.

Если понадобится отключать целую фичу на отдельных машинах, добавим ей один переключатель, управляющий одновременно системной и пользовательской частями.

Одна фича — одна внешняя точка подключения. Различия между ОС и взаимодействие с Home Manager остаются внутри её директории.

Предложение по новой архитектуре. Примеры показывают целевую организацию; рефакторинг репозитория этим документом не выполняется.
